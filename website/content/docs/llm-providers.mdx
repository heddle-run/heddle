---
title: LLM Providers
description: Configure OpenAI, vLLM, Ollama, or any compatible endpoint.
---

heddle supports multiple LLM providers out of the box. Switch providers by changing a few
lines in your document. No code changes needed.

A model config is an entry under the document's top-level `models` map, or the same shape
written inline wherever a model is expected (an agent's `model`, an `llm` step's `model`,
a transform's `model`). `provider` selects the client; everything speaks the OpenAI chat
completions API underneath.

| `provider` | `url` | Notes |
|------------|-------|-------|
| `openai` | optional | Talks to the OpenAI API |
| `openai-compatible` | required in practice | Any OpenAI-compatible endpoint |
| `vllm` | required in practice | Self-hosted vLLM |
| `ollama` | defaults to `http://localhost:11434/v1` | Local Ollama |

Every config needs a `provider` and a `model` — the model id the endpoint knows. These
four are the providers heddle implements; `api_key`, `url` and `params` are the only other
fields a builtin accepts, and an unknown field is refused at load rather than carried as
decoration.

Any other `provider` value must come from a loaded plugin. A plugin can supply a provider
type that answers model calls itself, which is how a document reaches an endpoint heddle
ships no client for. It may not claim one of the four above: a flow writing
`provider: openai` reaches heddle's own client whatever is loaded. See
[Plugins](/docs/plugins).

## OpenAI

```yaml
models:
  main:
    provider: openai
    model: gpt-4o
```

Set your API key in the environment:

```bash
export OPENAI_API_KEY=sk-...
```

Or reference an environment variable from the document:

```yaml
models:
  main:
    provider: openai
    model: gpt-4o
    api_key: $OPENAI_API_KEY
```

## OpenAI-compatible

For any endpoint that implements the OpenAI API format:

```yaml
models:
  mine:
    provider: openai-compatible
    model: my-model
    url: https://my-endpoint.com/v1
    api_key: $MY_API_KEY
```

## vLLM

For self-hosted models via vLLM:

```yaml
models:
  llama:
    provider: vllm
    model: meta-llama/Llama-3.1-8B
    url: http://localhost:8000/v1
    api_key: $VLLM_API_KEY
```

## Ollama

For local models via Ollama:

```yaml
models:
  local:
    provider: ollama
    model: llama3.1
```

`url` defaults to `http://localhost:11434/v1`, and `api_key` may be omitted entirely:
Ollama ignores the key, so heddle supplies a placeholder where the client insists on one.
An Ollama running elsewhere is a `url` away.

## Generation parameters

`params` carries generation parameters, passed through to the endpoint as written:

```yaml
models:
  fast:
    provider: openai
    model: gpt-4o-mini
    params:
      temperature: 0
      max_tokens: 512
```

`temperature`, `max_tokens` and `top_p` are the three heddle sends, and the three the
format accepts — a parameter heddle would drop on the floor is refused at load instead of
carried.

## API keys

`api_key` can reference an environment variable using the `$` prefix:

```yaml
api_key: $MY_API_KEY
```

heddle resolves these from your shell environment at the **first model call**, not at
load time, and fails with a clear error if the variable is unset. A value without a `$`
prefix is used literally. Because resolution is deferred, `heddle validate` never reaches a
credential: a document naming `$OPENAI_API_KEY` validates with nothing in the environment.

`heddle run` looks ahead of that. Before the run starts it reads every variable the
document's `api_key` fields name and asks for the ones this shell does not have:

```
OPENAI_API_KEY is not set, and this flow reads it from the environment.
An answer is used for this run only — it is not echoed, and it is not written anywhere.
Press enter to leave one unset.

  OPENAI_API_KEY:
```

What you type is used by that process and nothing else: it is not echoed, and nothing is
written to disk. Export the variable to stop being asked. Pressing enter leaves it unset
and the run goes ahead — a variable named on a branch the run never takes is one the run
never needs, and whatever is skipped fails where it always did.

The question needs a terminal on both stdin and stderr, so a pipeline, a CI job, a server
or a `--protocol` stream is never asked and fails at the first model call exactly as
before. [`--no-ask-env`](/docs/cli-reference#heddle-run) turns it off on a terminal too.

<Callout type="warn">
**This resolution is conditional, and the condition is who wrote the document.** A server
started with `--allow-request-code` refuses `$VAR` in a submitted document entirely. The
reference is not restricted to model credentials, so resolving it would let a caller read
any variable in that process and send it wherever their own `models` entry points, and the
"is not set" error would answer whether a given variable exists. Documents you run
yourself resolve normally; documents a caller submits must carry their credential
literally.
</Callout>

<Callout type="warn">
A config with no `api_key` leaves the key to the OpenAI client, which reads
`OPENAI_API_KEY` from the environment and refuses to be built without it — so an
`openai-compatible` or `vllm` model with no `api_key` fails at the first model call even
when the endpoint checks no key. For local servers, either set any placeholder value or
write one into the document:

```bash
export VLLM_API_KEY=local
```

`ollama` is the exception: heddle fills the placeholder itself, so an Ollama config needs
no key anywhere.
</Callout>

<Callout type="warn">
Tools launched by a flow inherit the full environment of the `heddle` process, API keys included. Only put executables you trust in `--tools-dir`.
</Callout>
