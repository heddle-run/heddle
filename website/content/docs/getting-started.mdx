## Installation

There is nothing to install. `npx` fetches the CLI and runs it:

```bash
npx @heddle-run/cli --help
```

Every `heddle` on this page can be spelled `npx @heddle-run/cli`. That is not a
shortcut around a missing install step; it is the shape of the thing. heddle is
a runtime you point at a document, so it belongs outside your project: no
dependency, no lockfile entry, nothing that has to be migrated when heddle
changes.

To keep it on the machine rather than fetching it each time, install it globally
via npm:

```bash
npm install -g @heddle-run/cli
```

Verify the installation:

```bash
heddle --help
```

heddle requires Node.js 18 or newer.

## Set an API key

The scaffolded project uses OpenAI, so export a key before running anything:

```bash
export OPENAI_API_KEY=sk-...
```

Every provider needs a resolvable key, including local ones. See [LLM Providers](/docs/llm-providers) for how to point a flow at Ollama or vLLM instead.

## Create your first agent

Scaffold a new project:

```bash
heddle init my-agent
```

This creates:

```
my-agent/
├── weave.yaml     # Your workflow definition
└── tools/
    └── example_tool.sh   # A sample tool
```

The generated document is a single agent with one tool. It declares one input, `query`,
and its prompt interpolates that value with `{{inputs.query}}`.

## Run the workflow

```bash
heddle run my-agent/weave.yaml \
  --tools-dir my-agent/tools \
  --input '{"query": "What is the Weave format?"}'
```

`--input` is a JSON object carrying the flow's declared inputs, and it is checked: an
input the document declares without a default is required, and a run missing one fails
before anything executes, naming the field. The run's result — the outcome's payload,
plus `outcome` saying which way the flow ended — is printed to stdout as JSON; progress
and errors go to stderr.

Add `--verbose` for per-step logging:

```bash
heddle --verbose run my-agent/weave.yaml --tools-dir my-agent/tools --input '{"query": "hello"}'
```

## Conversations

`--session` keeps a run in a conversation and hands the agent the turns before it. Each command is one turn:

```bash
heddle run my-agent/weave.yaml --tools-dir my-agent/tools --session my-first --input '{"query": "hello"}'
heddle run my-agent/weave.yaml --tools-dir my-agent/tools --session my-first --input '{"query": "and again?"}'
```

Sessions live in `~/.heddle/sessions/`. `heddle sessions ls` lists them and `heddle sessions show <id>` prints a transcript. [Sessions](/docs/sessions) covers the rest: what is on disk, runs that survive a dead process, and runs that stop to wait for a person.

## Interactive chat mode

For debugging and exploration, add `-i`:

```bash
heddle run my-agent/weave.yaml --tools-dir my-agent/tools -i
```

That conversation lasts as long as the terminal. Add `--session <id>` to keep it, and reopening with the same id starts on the conversation so far. Type `/exit` to quit.

Your message is bound to the first input the flow declares, falling back to `query` if it
declares none.

## Validate a spec

Check your workflow before running it:

```bash
heddle validate my-agent/weave.yaml --tools-dir my-agent/tools
```

This runs the whole validation the format defines: the document's own shape, then every
reference — branch targets, template producers, plugin components — then the graph, and
finally that an executable exists for every tool the flow names. A flow that validates is
a flow that starts; anything discoverable at load time fails here, with exit code 1,
rather than mid-run.

## Share it

Once the agent works, hand it to someone as one file: the spec, the tools and their
executable bits, everything.

```bash
heddle bundle my-agent/weave.yaml --tools-dir my-agent/tools -o my-agent.heddle
```

```bash
heddle run my-agent.heddle --input '{"query": "hello"}'
```

The receiver needs heddle and an API key. A spec names its key as `$ENV_VAR`, resolved on
the machine that runs, so credentials never travel. See [Bundles](/docs/bundles).
