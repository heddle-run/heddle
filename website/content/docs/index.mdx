title: Introduction
description: A runtime for Weave flows. The workflow is a document; heddle is what you point at it.
---

**heddle needs no SDK.** Most agent frameworks are libraries: you install one, import it,
and assemble the graph in code, so the agent ends up depending on the library's
abstractions. heddle inverts that. The flow is a document you write, and heddle is a
runtime you point at it. Nothing in the document imports anything, and nothing in your
project depends on heddle's types.

The document is a [Weave](/docs/flows) flow, in YAML or JSON: `weave: 1` at the top, the
inputs a run must be given, the model each agent calls, the tools they may use, and an
ordered list of steps. Wiring is implied — by list order, and by `{{references}}` between
steps — so there are no ids, no edge lists, and no ceremony.

**One document runs two ways.** `heddle run` executes it on your machine; `heddle-server`
serves it over HTTP with the run streamed back as it happens. There is no rewrite between
them and no separate deployment format: the same file, pointed at by a different
program.

## Quick start

```bash
npm install -g @heddle-run/cli
```

Scaffold a project, then run it:

```bash
heddle init my-agent
cd my-agent
heddle run weave.yaml --tools-dir tools --input '{"query": "hello"}'
```

`--input` is JSON carrying the flow's declared inputs. The scaffolded document declares
one, `query`, and its prompt references `{{inputs.query}}`; a run that omits a required
input fails before anything executes, naming the field.

<Callout>
Set `OPENAI_API_KEY` before running, or point the document's `models` entry somewhere that
needs no key. A document may write `api_key: $OPENAI_API_KEY` and heddle resolves it from
the environment, with one exception covered in [LLM providers](/docs/llm-providers).
</Callout>

## What happens when you run it

```
document → parse → resolve → compile → execute
```

Validation is two passes, and both run at load time. The first reads the document alone,
strictly: every key known, every name well-formed, unknown keys refused. The second checks
what the document means: that every branch target lands, that every `{{reference}}` names
a value its producer actually writes on every path, that every plugin component is
provided and valid, and that the graph reaches an outcome.

`heddle validate` runs everything up to execution — so a flow that validates is a flow
that starts, and anything discoverable at load time fails there rather than mid-run.
